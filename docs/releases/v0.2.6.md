# MikuBox v0.2.6

本版补上 MikuRay UI 重写后缺失的代理组界面(修复 #2)。导入订阅链接后,配置里的策略组此前只能在全局模式的出口选择里看到,默认的规则模式没有任何入口 —— 而规则模式恰恰是按这些策略组路由的。

## 代理组

- 主页模式栏第二行在规则模式下显示「代理组」,打开即按组列出配置声明的全部策略组与成员,可逐个切换每组使用的节点。全局模式仍显示当前出口,直连模式不展开。
- 未连接时列出配置声明的成员,选择会保存并在连接后下发;已连接时改用核心的实际数据,包含 provider 提供的节点与最近测量的延迟。
- 面板提供「测速」(并发探测、逐个回填)与「按延迟排序」;自动组(url-test / fallback / load-balance / relay)额外提供「自动选择」,可取消已钉选的节点。
- 组与成员的选择按配置文件与组分别保存;更换配置后已不存在的组或节点会丢弃旧选择并在日志中说明。
- 成员由 provider(`use:`)提供的组离线无法列举,面板会如实说明,不显示伪造的节点名。

## 无障碍

- 面板中的当前分组以「已选中」状态报告给读屏软件,不再只靠颜色区分。

## 验证

69 项单元回归、lint(0 错误)、本地化覆盖与无障碍审计通过;API 34 x86_64 模拟器完成:离线选择后连接生效(`using 🚀 节点选择[JP-01]`)、在线切换与嵌套自动组钉选(`using 🚀 节点选择[SG-01]`)、测速得到实际数值并按延迟排序、规则 / 全局 / 直连三种模式的入口行为核对。完整记录见 `docs/proxy-groups-2026-10-05.md`。

已知限制:Go 侧测试仍由 CI 覆盖,本机不跑;面板中的延迟是核心最近一次测量值,自动组的实际出口由核心在运行时决定,离线无法预知。
