# MikuBox v0.2.8

本版加入 **AnyTLS** 支持:订阅里的 `anytls://` 链接可以解析,手动添加也有对应表单。顺带修复订阅中 `alpn` 列表写错层级、导致整份配置无法解析的问题。

## AnyTLS

- 订阅解析:`anytls://[user[:password]@]host:port?sni=&insecure=1&hpkp=&alpn=#name`。密码取 userinfo(`user:pass` 形式取冒号之后的部分,与 mihomo 自身的链接转换一致);支持 `sni`、`insecure` / `allowInsecure`、`hpkp` / `fp`(客户端指纹)与 `alpn`。此前这类链接会被整行跳过,所以只含 anytls 的订阅会报「未找到兼容 Mihomo 的代理链接」。
- 手动添加新增 **[AnyTLS]**:服务器 / 端口 / 密码 + TLS 字段(SNI、ALPN、客户端指纹、允许不安全证书),新建草稿默认选中 TLS。
- 分享单个节点、以及主页节点行的协议标识同样支持 AnyTLS。

## 修复

- `alpn` 之前被写在代理项之外(缩进少一层),含该字段的订阅配置会整份解析失败;现在写在节点字段层,并加了回归测试(既断言缩进,也断言整份 YAML 可解析)。

## 验证

71 项单元回归、lint(0 错误)、本地化覆盖与无障碍审计通过;API 34 x86_64 模拟器上完成:仅含 anytls 链接的 base64 订阅导入成功并生成正确配置;连接后核心日志为 `using PROXY[AnyTLS-HK]`,经本机 anytls 服务端实测转发成功(HTTP 请求 200、主页出口 IP 正常读出);手动表单保存的节点为合法 anytls 配置,核心按该节点发起拨号。

已知限制:Go 侧测试仍由 CI 覆盖,本机不跑。
